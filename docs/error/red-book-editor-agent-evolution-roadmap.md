# Red Book Editor 演进路线

> 这份路线是当前有效的产品和 Agent 演进依据。历史 change、学习记录和问题修复记录保留当时事实，但不覆盖本文档定义的当前产品边界。

## 1. 产品先于 Agent

项目的核心不是“让用户看到一个 Agent”，而是：

> 用户输入本次想写的主题和原始素材，结合账号领域、定位和表达风格，得到一篇可编辑、可复制的小红书文案。

Agent 只是服务端内部实现。任何新增 Agent 能力都必须回答：它是否让标题更贴合主题、正文更自然、事实更可靠或用户修改成本更低。如果只是增加 trace、工具或内部术语，不应进入 C 端。

## 2. 当前目标产品流

```text
账号领域 / 定位 / 语气
          +
内容主题 / 原始素材 / 领域补充
          +
表达风格
          ↓
通用 Content Agent
理解 → 组织 → 生成 → 检查 → 修订
          ↓
标题 / 正文 / 话题 / 配图建议
          ↓
编辑 / 复制 / 保存
```

标题和选题角度必须围绕用户明确的主题。限制条件、取舍和背景默认是辅助信息，除非用户明确把它们设为主题。

## 3. 产品表面与内部系统

### C 端保留

- 账号选择和账号配置；
- 内容主题与原始素材输入；
- 领域补充信息；
- 表达风格选择；
- 标题、正文、话题、配图建议；
- 编辑、复制、保存和重试；
- 真实阻断问题的最小可行动提示。

### 服务端/评测保留

- Agent Runtime 和预算控制；
- Domain Strategy Pack；
- Fact Ledger、Claim Audit 和安全门禁；
- AgentRun 状态、事件和失败诊断；
- 真实模型评测、质量门禁和成本统计。

### 不作为主流程

- Agent 执行过程可视化；
- 模型思考或工具调用说明；
- 完整来源证据和声明审计；
- 复杂 Diff、字段候选历史；
- 发布数据和素材库复杂管理。

## 4. 当前重构顺序

### 阶段 0：内容优先重构

这是当前进行中的 change：

1. 冻结内容优先产品契约；
2. 将 `SourceExperience` 兼容转换到 `ContentBrief`；
3. 增加明确的 `focus`，让标题和 topic angle 以用户主题为最高优先级；
4. 抽象领域策略包，先接入 parenting；
5. 把内部诊断和用户结果分成两个投影；
6. 移除 C 端 trace、Claim Audit 和无关审核提示；
7. 让账号/领域/栏目上下文真正驱动生成；
8. 为普通内容、周岁宴主题、医疗风险和来源外经历建立回归案例。

### 阶段 1：稳定内容质量

- 以主题重心、账号匹配、表达自然度、事实保真和人工修改成本建立评测；
- 修复自然中文改写被逐字事实匹配误判的问题；
- 将真实 blocking 风险与普通质量不确定性分开；
- 统一主生成、异步 AgentRun、保存和字段重生成路径。

### 阶段 2：账号和领域扩展

- 支持多个账号和真实账号/栏目选择；
- 完善 parenting Domain Strategy Pack；
- 增加第二个领域前，先证明 Domain Pack 不需要复制通用 Agent；
- 每个新领域必须有独立策略版本、输入定义、质量案例和安全评测。

### 阶段 3：次级生产和复盘能力

- 在核心创作稳定后恢复版本历史和字段候选历史的次级页面；
- 增强用户素材管理和配图工作流；
- 提供手动发布记录和基础复盘；
- 这些能力不能重新占据首次生成结果的主空间。

### 阶段 4：谨慎扩展 Agent 能力

只有当主题、事实、领域策略和评测稳定后，才评估：

- 经过授权的领域资料检索；
- RAG；
- MCP 工具；
- 多 Agent 协作。

这些能力必须服务于用户内容结果，不能成为产品展示目标。

## 5. Agent 架构目标

```text
Account Profile
        +
Domain Strategy Pack
        +
ContentBrief
        +
Style Profile
        ↓
Generic Content Agent
        ↓
User Result Projection
        ↘ Internal Diagnostics
```

Domain Strategy Pack 至少包含：

- `domain_id`、版本和展示名称；
- 补充输入 schema；
- 生成上下文；
- 质量规则；
- 安全政策；
- 工具权限；
- 用户问题投影。

通用 Agent 不直接包含育儿、金融、法律等领域分支。系统安全内核仍由代码控制：密钥隔离、账号隔离、工具白名单、结构化输出、预算、超时、事实边界和导出门禁不能交给模型。

## 6. 质量门禁

每次产品或 Agent 迭代至少需要验证：

| 维度 | 核心问题 |
| --- | --- |
| 主题重心 | 标题和开头是否围绕用户真正想写的主题 |
| 账号匹配 | 是否符合账号领域、定位和语气 |
| 表达自然 | 是否像用户会使用的小红书文案，而不是系统报告 |
| 事实保真 | 是否新增了关键经历、结果、背书或产品属性 |
| 安全边界 | 是否阻止真实高风险内容，且不误报普通内容 |
| 修改成本 | 用户需要改多少才能直接使用 |
| 页面负担 | 是否加入了用户不需要理解的内部信息 |

“Agent trace 更完整”不是 C 端质量指标。

## 7. 文档纪律

- 产品行为先更新 OpenSpec 和 `docs/product/`；
- 跨端字段先更新 `docs/contracts/CONTENT_WORKFLOW_CONTRACT.md`；
- 领域和 Agent 架构决策同步更新 `docs/decisions/`；
- 学习记录可以保留历史过程，但必须标明它不等于当前产品契约；
- 归档 change 和 `docs/error/change-fix-history.md` 是历史记录，不用回写成当前实现；
- 每个 change 完成并归档后，按项目约束同步修复历史和创建 Git commit。

## 8. 本轮未覆盖项

- 当前只接入 parenting Domain Strategy Pack，尚未实现第二个真实领域及其独立安全评测。
- 账号设置页已经通过真实 API 保存账号定位、语气和宝宝月龄，但栏目启用/停用控件仍是静态占位，尚未接入服务端栏目管理。
- 真实 DeepSeek 基线和人工评分需要外部模型凭据，本轮未运行；评测样例、scorecard 和 manifest 已完成同步并通过本地校验。
- 内部诊断继续保存在服务端模型和 AgentRun 路径，本轮没有新增独立的授权诊断接口。
