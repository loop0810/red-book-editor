## Context

本 change 的要求见 `proposal.md` 和 `specs/note-creation/spec.md`。当前生成链路已经有
ContentBrief、Fact Ledger、风格 Agent 和最终质量校验，但原始素材同时被当成事实来源和可直接
改写的正文，质量检查主要验证事实出现和长度，无法阻止模型复用原句。

实现必须继续满足以下边界：客户端只提交主题和正文素材，不直接调用模型；服务端不能凭空增加
用户经历；领域安全审核仍然是最终门禁；内部事实账本和 Agent 诊断不进入普通编辑页面。

## Goals / Non-Goals

**Goals:**

- 让粗略输入经过“事实整理 → 内容角度 → 结构化写作 → 事实与复用校验”后成为可编辑的小红书文案。
- 将“保留事实”和“保留原文”明确分开，正文开头不再机械复用输入。
- 允许安全的编辑性丰富，包括重排、归纳、转场、钩子、段落结构和不增加具体事实的总结。
- 让质量失败反馈可以驱动 Agent 重写，而不是返回表面完整但不可直接使用的伪成功内容。
- 保持现有 ContentBrief、保存、恢复和字段重生成接口兼容。

**Non-Goals:**

- 不增加“发生了什么/我做了什么/观察到什么”等新的用户输入区域。
- 不允许模型创造新的具体事件、人物、结果、时间线、专业背书或用户未表达的真实感受。
- 不在本 change 中引入第二个模型供应商、自动发布或复杂的用户写作模式选择。

## Decisions

### 1. 把原始正文作为素材便签，而不是草稿

保留现有 `focus`、`raw_material` 和领域上下文边界，但在 Agent 语义中明确：

```text
ContentBrief
├─ focus: 这篇内容真正要写什么
├─ raw_material: 用户的事实便签/流水账/关键词
└─ domain_context: 可选领域补充
```

模型可以改变句式、顺序和段落，但事实来源仍然只有 ContentBrief 和账号/栏目上下文。用户
界面只需要修改字段提示和示例，不重新拆分表单。

### 2. 采用内部两阶段写作，不把素材直接喂给单次扩写

Agent 内部先形成不可直接展示的素材理解：

1. 提取可确认事实、观察、限制条件、用户观点和未知信息。
2. 依据 focus 与风格档案选择叙事角度、读者价值和正文结构。
3. 从角度和事实卡片重新起草正文，不以 raw_material 的第一句话作为开头。
4. 经过事实保真、结构丰富和原文重叠检查后再定稿。

选择内部两阶段而不是单纯增加“不要复制原文”的 Prompt，是因为单一 Prompt 无法证明模型
已经完成了素材理解，当前基于事实出现的检查也会奖励复制。两阶段可以复用现有 Agent Runtime
和 Fact Ledger，不需要给用户增加额外输入。

### 3. 定义允许的编辑性丰富边界

允许的丰富包括：

- 将流水账改写成开头、过程、细节、感受/观察和收束的自然段；
- 增加不改变事实的连接句、解释句、标题钩子和段落过渡；
- 将用户明确表达的取舍归纳为内容观点；
- 用中性的编辑性语言总结已发生的事实。

禁止的丰富包括：

- 增加用户未提供的具体人物、地点、动作、礼物、对话、结果或时间线；
- 把模型推断的情绪、满意度、因果关系或专业结论写成用户真实经历；
- 用风格档案中的示例替代本次用户素材；
- 通过重复原文来满足正文长度要求。

默认不把“我很感动”“效果特别好”等第一人称或结果性句子当成可自由补全的编辑语言，除非
素材中已有对应事实或观点。中性总结可以生成，但必须能由已提取事实直接支持。

### 4. 用互补质量门禁替代单纯长度门禁

最终校验至少包含四类结果：

- **事实覆盖**：关键事实、限制条件和用户明确观点仍能在正文中找到对应表达；允许自然改写，
  不要求逐字匹配。
- **内容丰富**：正文有新的开头、明确的段落组织、过程细节和收束，不能只把输入拆段或追加
  连接词；长度只作为弱信号，不再是主要质量目标。
- **原文重叠**：检测正文开头和正文整体的连续原文复用，短主题、专有名词、数字和必须保留的
  事实片段需要排除或降低权重；超过阈值时要求 Agent 重写。
- **事实边界**：继续执行现有安全审核和声明审计，任何未被来源支持的关键经历或风险结论不能
  以“丰富”为理由通过。

若重写预算耗尽仍无法同时满足事实和反复用门禁，系统保留用户素材并返回可行动失败，不返回
看起来完整但仍机械复读的草稿。

### 5. 让风格档案决定结构，不让通用规则制造模板

经验、科普和软文继续使用各自风格档案的钩子、段落和语气规则；通用门禁只要求“重新组织、
事实可追溯、不可虚构”。这样可以避免为了通过检查而给所有内容套用相同的“场景—过程—结果”
模板。每种风格的测试案例都需要包含短素材和粗略素材，而不是只测完整长稿。

### 6. 保持输出契约，新增约束放在内部生成阶段

对客户端保持现有标题候选、正文、话题、封面文案和配图建议结构，不新增素材拆分字段。内部
可以增加素材理解或质量诊断对象，但不写入用户可见正文、普通编辑页面或持久化的模型原始响应。

字段单独重生成也必须把当前正文视为可编辑内容上下文：重生成正文时要重新组织现有素材和
主题，不得直接返回原正文；重生成其他字段时不得修改用户已编辑的正文。

## Risks / Trade-offs

- [Risk] 中文短句、专有名词或数字可能被误判为原文复用 → 使用连续片段长度和覆盖比例的组合，
  对 focus、数字、专有名词和必要事实片段做保护，并用真实中文案例校准阈值。
- [Risk] 模型为了避免复制而遗漏关键事实 → 先建立事实理解，再做覆盖检查；事实缺失优先级高于
  反复用检查，失败时要求修订而不是直接放行。
- [Risk] 两阶段写作增加模型调用次数和响应时间 → 优先在现有 Agent 循环中复用上下文和工具，
  只在素材复杂或首轮质量失败时触发额外整理/重写；保留现有超时和重试保险丝。
- [Risk] 编辑性总结被误解为用户真实观点 → 限制具体第一人称和结果性表达，继续将来源事实与
  模型生成声明分开审计。
- [Risk] 质量门禁过严导致粗略但有效的内容频繁失败 → 把原文重叠作为可修订问题而不是安全阻断，
  以“事实保留 + 内容明显更可用”为最终验收标准。

## Migration Plan

1. 先更新 Content Agent 的素材语义、风格档案提示和内部质量检查，不改变客户端 API 结构。
2. 增加短素材、流水账、关键词和高复用输入的服务端回归案例，校准事实覆盖和原文重叠规则。
3. 更新 Flutter 输入提示，并确认本地草稿恢复仍只恢复主题、素材和图片。
4. 在 stub、DeepSeek 模拟网关和真实评测案例上分别验证：事实不丢、正文不复读、结构有丰富度、
   不产生未提供的具体经历。
5. 若新门禁造成已有草稿无法重生成，保留旧草稿可编辑；仅对新生成和明确请求重生成的内容应用
   新规则。必要时可回滚提示和门禁实现，不需要数据库迁移。

## Open Questions

- 本 change 先使用统一的最低结构要求，风格差异继续由现有风格档案控制；不同表达形式是否需要
  独立的长度阈值，留待后续评测数据充分后再决定，不阻塞本 change。
