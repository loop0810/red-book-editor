## Why

项目当前已经能够调用 Agent 生成小红书文案，但产品体验逐渐偏离了核心目标：内部的 Agent trace、事实账本、声明审计和领域安全提示直接出现在 C 端页面，普通用户看到的是系统如何工作，而不是一篇可编辑、可复制、符合账号定位的文案。与此同时，输入模型没有明确记录“这篇内容真正想写什么”，导致标题可能把限制条件或附属细节误当成主题。

现在需要先完成一次内容优先的产品重构，重新确定用户界面、生成契约和 Agent 架构的边界，再开始代码实现，避免继续以学习 Agent 为理由向 C 端堆叠内部能力。

## What Changes

- **BREAKING** 将产品核心重新定义为：用户输入主题和原始内容，选择账号已配置的领域与表达风格，获得符合账号定位的小红书标题、正文、话题和配图建议。
- 将当前强绑定育儿经历的输入模型调整为通用 `ContentBrief`：明确的内容主题/重心、原始素材和可选领域上下文；育儿月龄等字段成为育儿领域策略包的可选补充，而不是通用输入前提。
- 在生成链路中明确区分内容重心、支持事实和限制条件，标题与选题角度必须优先围绕用户指定主题，不能把“不要做什么”自动当成主题。
- 新增可扩展的领域策略包概念；育儿作为第一个策略包，负责领域字段、写作上下文、质量规则和安全策略，通用 Content Agent 不再硬编码育儿分支。
- **BREAKING** 将 Agent trace、Fact Ledger、Claim Audit、运行阶段、模型诊断和详细审核命中定义为服务端内部能力，不再作为普通 C 端编辑页面的展示内容。
- 将用户可见质量提示收敛为必要且可行动的提示：只有真实阻断问题才影响用户使用，并使用与实际问题匹配的说明；普通的内部不确定性和审计证据不应污染生成结果页面。
- 精简生成和编辑页面，保留主题输入、原始素材、风格选择、标题、正文、话题、配图建议、编辑、复制、保存和重新生成；版本 Diff、候选历史、发布数据和 Agent 可视化移出主流程，作为后续能力或内部工具。
- 让账号领域、定位、语气和栏目上下文真正成为生成请求的一部分，移除客户端依赖手工硬编码账号/栏目 ID 的产品路径。
- 同步更新现行 OpenSpec specs、API 契约、产品说明、Agent 架构决策和演进路线；历史归档 change 保持原样，作为真实开发过程记录。

## Capabilities

### New Capabilities

- `domain-strategy-packs`: 以版本化策略包描述领域专属输入、上下文、质量规则、安全政策和可用工具，支持育儿之外的未来领域。

### Modified Capabilities

- `account-workspace`: 账号配置需要包含稳定的领域标识，并真正参与内容生成；账号设置不再只是客户端本地演示页面。
- `note-creation`: 从“育儿经历表单”调整为“主题 + 原始素材 + 可选领域上下文”的内容优先创作流程，并精简用户可见结果和交互。
- `agent-runtime-workflow`: Agent 负责内部内容生成与质量循环，trace 和运行诊断只服务内部调试、评测和运维，不构成 C 端产品功能。
- `content-safety-review`: 继续保留服务端安全边界，但分离内部审核证据与用户可见提示；只有实际阻断问题才阻止用户使用，领域无关或低置信度审计不能默认显示为医疗/用药提示。
- `fact-ledger-and-claim-audit`: 事实账本和声明审计继续作为内部质量保证，不把脆弱的文本匹配结果直接当作用户错误；需要定义自然改写、主题重心和来源外关键事实的不同处理方式。
- `ai-editing-interactions`: 编辑建议、版本和 Diff 保留为可演进的能力，但不再定义首次生成页面的信息架构；质量门禁只由真实领域阻断决定。
- `agent-run-lifecycle`: 异步运行继续支持持久化、取消、恢复和内部诊断，但客户端默认只消费内容结果与可执行状态，不消费运行步骤。
- `agent-evaluation`: 评测从“育儿 Agent 是否完成流程”扩展为通用内容 Agent 的主题重心、账号/风格适配、事实保真、用户价值和编辑成本评测，育儿仍是首个领域样本。
- `asset-and-publish-records`: 素材和发布记录不再占据首要创作路径，保留服务端能力并降为次级/后续产品能力。

## Impact

- `client/`：重构内容输入和编辑页面的用户流程，隐藏内部 Agent/审核细节，移除硬编码账号和栏目依赖，保留小红书内容编辑与复制核心。
- `server/`：抽象通用 Content Agent 上下文和 Domain Strategy Pack，调整输入、输出、审核投影和领域策略边界；保留内部 trace、Fact Ledger、Claim Audit 和评测能力。
- `docs/contracts/CONTENT_WORKFLOW_CONTRACT.md`：新增 `ContentBrief`、领域策略上下文和用户结果投影，重新定义 `AgentTrace`、`ReviewResult` 和 `ClaimAudit` 的内部边界。
- `openspec/specs/`：同步账号、创作、安全、Agent runtime、事实审计和素材/发布能力的现行要求。
- `docs/product/`、`docs/decisions/`、`docs/error/` 路线说明和 `docs/learning/`：明确产品价值优先于 Agent 可见性，避免未来迭代再次把内部学习能力误当成 C 端功能。
- 不在本 change 中接入更多模型供应商、不实现自动发布、不实现完整多领域业务；本 change 先完成产品边界、数据契约和可扩展架构设计，随后按 tasks 实现第一版重构。
