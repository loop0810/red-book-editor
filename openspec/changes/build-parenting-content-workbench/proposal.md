## Why

当前没有一个围绕单一小红书账号的内容生产工作台，真实育儿经历需要在选题、写作、配图和发布准备之间反复整理。这个变更将把用户对 0～2 岁宝宝日常经验的了解沉淀为可持续使用的账号配置和内容工作流，并以 Flutter 移动端支持 iOS 与 Android 使用。

## What Changes

- 建立 monorepo，同时管理 Flutter 移动客户端和 Python 内容服务端。
- 新增单账号工作台，维护账号定位、宝宝月龄、表达风格、内容边界和栏目。
- 新增基于真实经历的笔记创作流程，生成选题角度、标题、正文、话题、封面文案和配图建议。
- 新增草稿保存、版本编辑、素材管理和发布记录。
- 新增服务端 Agent 工作流和内部内容检查，识别医疗诊断、用药建议、虚构经历、夸大承诺和偏离账号定位的内容。
- 提供移动端复制标题、复制正文和导出素材能力；V1 不包含小红书自动发布、账号登录或互动操作。
- 建立客户端与服务端之间的类型化 API 契约和错误语义。
- 为后续多账号、多领域和矩阵数据复盘保留账号、栏目、内容和数据的扩展模型。

## Capabilities

### New Capabilities

- `account-workspace`: 管理单一育儿账号的定位、风格、内容范围和栏目配置。
- `note-creation`: 从用户提供的真实育儿经历生成、编辑并保存小红书图文笔记。
- `content-safety-review`: 对内容进行账号边界和医疗相关风险检查，并在高风险场景阻止直接生成建议。
- `asset-and-publish-records`: 管理笔记素材、草稿版本、复制导出和手动发布记录。

### Modified Capabilities

无。

## Impact

- 建立 `client/` Flutter 应用和按功能拆分的 Dart packages，支持 iOS 与 Android。
- 建立 `server/` Python 模块化单体，按参考 Kitchen 仓库采用 `src/`、`tests/`、`migrations/` 和锁定依赖的组织方式。
- 新增客户端、服务端和共享 `docs/` 分区；跨端请求、响应、错误和数据语义集中记录在 contracts 文档中。
- 需要接入可替换的文本生成模型服务；图片生成不是 V1 的阻塞依赖。
- 需要服务端数据库和文件存储保存账号、笔记、宝宝照片及封面素材，并注意儿童隐私。
- V1 不依赖小红书发布 API，不自动登录、发布、点赞、评论或抓取账号数据。
- 后续多账号矩阵能力将基于本次建立的账号、栏目、内容和发布数据结构扩展。
